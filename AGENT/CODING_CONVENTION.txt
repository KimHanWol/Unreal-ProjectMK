ProjectMK 코딩 컨벤션 요약

이 문서는 빠르게 읽는 요약본이다.
공식 기준은 `CODING_CONVENTION.md` 이고, 수정할 때는 항상 함께 맞춘다.

1. 기본 원칙

- Unreal Engine 기본 스타일과 프로젝트 기존 구조를 우선한다.
- 주변 코드와 같은 구조, 정렬, 네이밍을 먼저 따른다.
- 불필요한 helper 함수는 만들지 않는다.
- 안 된다고 임시 코드와 우회 코드를 덕지덕지 붙이지 않는다.
- 정석적으로 되어야 하는 부분이면 먼저 점검 방법과 확인 순서를 정리하고 원인 확인 뒤에만 수정한다.

2. 인코딩과 공백

- 코드와 문서는 `UTF-8 BOM`, `CRLF` 를 사용한다.
- 마지막 줄바꿈을 유지한다.
- trailing whitespace 를 남기지 않는다.
- 함수 묶음과 변수 묶음 사이에는 한 줄 개행을 둔다.

3. 파일 / include

- Unreal placeholder 주석은 넣지 않는다.
- `// LINK` 가 있는 파일은 기존 형식을 유지한다.
- 헤더는 `#pragma once` 를 사용한다.
- `*.generated.h` 는 마지막 include 로 둔다.
- `.cpp` 에서는 자기 헤더를 가장 먼저 include 한다.

4. 네이밍

- PascalCase 를 사용한다.
- bool 은 `b` 접두어를 사용한다.
- 같은 역할의 함수는 같은 접두어를 사용한다.

5. 함수 이름 규칙

- `On~` : 바인딩 콜백
- `Try~` : 조건 확인 뒤 시도
- `Apply~` : 상태나 효과 적용
- `Clear~` : 적용 상태 해제
- `Update~` : 현재 상태 기준 갱신
- 위젯 공통 최신화 진입 함수는 `UpdateWidget()` 을 사용한다.
- 위젯 세부 갱신은 private `Update~` 로 나눈다.
- `Refresh~` : UI 다시 표시
- `Find~` : 탐색
- `Get~` : 이미 가진 값 반환
- `Calculate~` : 계산 결과 반환
- `Is~`, `Can~`, `Has~` : 조건 판단

6. 구조 원칙

- `Manager` 는 공용 데이터, 설정, 자산 조회를 맡는다.
- `Subsystem` 은 월드 흐름과 생명주기 제어를 맡는다.
- `Actor` 는 조합과 상위 흐름을 맡는다.
- `Component` 는 재사용성이 높거나 책임 분리가 꼭 필요할 때만 분리한다.
- 체력, 산소 같은 실제 수치는 GAS `AttributeSet` 을 기준으로 둔다.

7. Widget 원칙

- 모든 UI 클래스는 `UMKUserWidget` 계열로 둔다.
- 공통 접근은 `UMKUserWidget` 의 공통 접근 함수로 처리한다.

8. 데이터 접근

- DataTable, DataAsset, 전역 설정값은 `UDataManager` 경유를 원칙으로 한다.
- 게임 로직에서 직접 `FindRow` 하는 구조는 지양한다.

9. UPROPERTY / UFUNCTION

- UObject 참조는 기본적으로 `UPROPERTY` + `TObjectPtr` 를 사용한다.
- 가능하면 `EditAnywhere` 보다 더 좁은 노출 범위를 사용한다.
- `BlueprintReadWrite` 는 꼭 필요할 때만 사용한다.
- 기본은 `BlueprintReadOnly` 로 둔다.

10. Tick / 이벤트 바인딩

- `Tick` 은 기본 선택지가 아니다.
- delegate, timer, overlap, attribute change, 명시적 갱신으로 대체 가능한지 먼저 본다.
- Widget 은 이벤트 기반 갱신을 우선한다.
- 이벤트 바인딩은 `BindEvents()` / `UnbindEvents()` 로 관리한다.

11. 선언 / 정의 순서

헤더 함수 선언 순서는 아래 기준을 따른다.

1. 생성자 / 소멸자
2. 엔진 override
3. `BindEvents()` / `UnbindEvents()`
4. 외부 상호작용 함수
5. 내부 동작 함수
6. 조회 / 계산 / 설정 / 유틸
7. `On~` 콜백
8. delegate 선언
9. 멤버 변수

- `.cpp` 구현 순서는 헤더 선언 순서와 맞춘다.
- 함수는 이름순이 아니라 역할순으로 묶는다.
- `Update~` 묶음 다음에 `On~ed` 콜백 묶음이 오면 한 줄 개행을 둔다.

12. 주석 / 임시 코드

- 주석은 꼭 필요할 때만 짧고 분명하게 남긴다.
- TODO 는 `// TODO: ...` 형식으로 작성한다.
- 임시 코드는 오래 남기지 않는다.
- 남겨야 하면 이유와 제거 조건을 주석으로 남긴다.

13. 마감 전 확인

- 직접 참조가 다시 섞여들어오지 않았는지 확인한다.
- Tick 과 이벤트 바인딩이 불안하게 섞여있지 않았는지 확인한다.
- Blueprint 노출 범위가 과하게 넓어지지 않았는지 확인한다.
- 가능하면 빌드와 최소 동작 확인까지 하고 마감한다.

14. 커밋 메시지

- 커밋 메시지는 제목 한 줄을 먼저 쓴다.
- 제목 다음에는 빈 줄 한 줄을 둔다.
- 그 다음 줄부터는 `- ` 뒤에 한 칸 띄우고 세부 사항을 적는다.
- 세부 사항은 변경 목적, 핵심 수정, 주의점 위주로 짧게 정리한다.

Implement skill tree menu interaction

- Add skill tree menu contents type and menu opening flow
- Add skill data-driven skill slot update and purchase handling
- Align widget update flow with shared MKUserWidget conventions
