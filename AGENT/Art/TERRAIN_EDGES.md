# 노출된 지형 가장자리

흙·잔디·돌·모래·얼음에 적용한다. 빈 공간뿐 아니라 서로 다른 지형의 접점도 울퉁불퉁하게 연결한다. 더 높은 우선순위의 재질이 이웃 셀의 가장자리 안쪽으로 이어지므로 흙과 돌 사이에 배경이 보이는 틈이 생기지 않는다. 버팀목·상점·숨김 경계는 지형 외곽 처리에서 제외한다.

## 시각 규칙

- 32×32 원본의 중심 24×24 픽셀은 모든 조합에서 그대로 유지한다.
- 빈 공간 및 다른 재질과의 경계에서 1~4픽셀의 불규칙한 굴곡을 만든다. 이전의 규칙적인 1~2픽셀 굴곡과 둥근 모서리 처리보다 변화가 크다.
- 돌기는 2~6픽셀의 불규칙한 폭으로 나누고 높이를 독립적으로 정한다. 바로 옆 한 픽셀만 섞어 어깨를 깎으므로 짧은 톱니와 평평한 끝을 유지하면서 직각으로 크게 꺾이는 부분을 줄인다. 블록과 면마다 시작점과 모양을 바꾸며, 전체 굴곡을 길게 보간하지 않는다.
- 서로 다른 재질의 접점은 이웃 원본 텍스처로 채우고, 같은 재질끼리는 연결한다. 흙과 잔디는 같은 재질 계열로 취급한다.
- 빈 공간에 노출된 가장자리에만 6% 음영을 적용하며, 내부 재질 접점에는 테두리 음영을 만들지 않는다.
- 블록 생성 위치에서 정한 형태값을 Custom Primitive Data 0번으로 모든 레이어에 공유한다. 낙하 중 위치가 바뀌어도 가장자리 모양이 흔들리지 않는다.
- 블록·광맥·손상 균열·완충 젤은 같은 외곽 마스크를 사용한다. 파괴 후 흩어지는 파편과 접촉 효과는 이 마스크로 자르지 않는다.
- 원본 PNG, 스프라이트 UV, 픽셀 밀도, 충돌 크기는 유지한다. 적용 대상은 UV 0~1을 사용하는 전체 32×32 셀이다. 아틀라스 패킹이나 다른 크기의 지형에 적용하려면 UV/해상도 규칙도 함께 수정해야 한다.

## 데이터와 구현

- BlockDataTable의 `bUseTerrainEdges`: 지형별 사용 여부.
- BlockDataTable의 `TerrainBlendPriority`: 흙/잔디 10, 모래 20, 얼음 30, 돌 40. 높은 재질만 낮은 재질 쪽으로 이어져 이중 띠나 빈 틈을 방지한다.
- DA_VisualStyle의 `TerrainEdgeMaterials`: 16개 공유 머티리얼 인스턴스. 인덱스 비트는 왼쪽 1, 오른쪽 2, 위 4, 아래 8이며 비트가 1이면 빈 공간 또는 다른 재질과의 경계다.
- 서로 다른 재질이 맞닿는 블록의 바탕은 동적 머티리얼에 네 이웃 텍스처와 채움 여부를 전달한다. 광맥·균열은 동일한 형태의 공유 마스크를 사용하므로 이웃 재질 위로 자기 광물이 튀어나오지 않는다.
- `/Game/Asset/ArtV2/Materials/M_TerrainEdges`: 기존 SpriteTexture와 VertexColor를 그대로 사용한다. 외곽 계산 소스는 [TerrainEdges.hlsl](TerrainEdges.hlsl)이다.
- LevelManagerSubsystem은 생성·채굴·설치·착지 시 해당 위치와 네 이웃을 갱신한다. 움직이는 붕괴 블록은 기존 낙하 Tick에서 실제 위치를 기준으로 서로 연결됐는지 계산한다. 정지 지형 전체를 매 프레임 검사하지 않는다.
- BlockBase는 비동기 스프라이트 로드 후, 보상 광맥 변경 후, 내구도/균열 갱신 후에도 같은 외곽 머티리얼을 적용한다.

## 재적용과 검증

1. 현재 C++ 모듈이 빌드된 에디터에서 PIE를 종료한다.
2. `AGENT/Scripts/ApplyTerrainEdges.py`를 Unreal Python으로 실행한다. ArtV1/ArtV2 기본 그래픽을 재적용했다면 마지막에 실행한다.
3. `RenderTerrainEdges.py` → Node에서 `VerifyTerrainEdgePixels.cjs`: GPU로 렌더링한 16조합에서 중앙 픽셀 동일성, 연결된 면 유지, 서로 다른 외곽 조합을 검사한다.
4. PIE 중 `VerifyTerrainEdges.py`: 현재 지형 이웃 상태와 외곽 비트, 광맥·균열 머티리얼 일치, 파괴 파편의 독립 머티리얼을 확인한다.

검증 결과와 미리보기는 `output/terrain-edges`에 저장한다. 테스트는 진행 저장을 차단하는 Playtest 세션에서 수행한다.

## 재질 접점 확장 검증

- Development Editor 빌드 성공.
- GPU 외곽 16조합과 이웃 재질 채움 5조합에서 중앙 24×24 픽셀 변경 수 0. 채움 조합의 빈 픽셀 수 0 확인.
- PIE 재질 접점 306개에서 우선순위, 이웃 상태, 채움 파라미터와 광맥·균열 마스크를 검사했다.
- 위쪽에 다른 재질이 있는 광맥 블록에 실제 내구도 피해를 적용해 균열 표시와 마스크 유지 확인. 왼쪽 블록 채굴 후 노출 비트 0 → 1 갱신 확인.
- 화면: `output/terrain-edges/material-transition-preview.png`. 최신 상세 결과는 `pixel-validation.json`, `runtime-validation.json`, `mining-validation.json`이다.

## 이전 버전 실행 확인

- Development Editor 빌드 성공.
- GPU 16조합의 중앙 24×24 픽셀 변경 수 0, 연결된 반대편 가장자리 유지 확인: `pixel-validation.json`.
- 실제 내구도 피해를 받은 광맥 블록에서 균열 표시와 세 레이어의 머티리얼 일치 확인. 왼쪽 블록 채굴 후 노출 비트 0 → 1 갱신 확인: `mining-validation.json`.
- 사방 지지 블록 제거 후 외곽 비트 15, 한 칸 낙하 관찰: `collapse-validation.json`.
- 발파 후 및 붕괴 후 지형 전체 이웃 상태/레이어 검사 오류 없음: `runtime-validation.json`.
- 원본 PNG 130개와 기존 보관 픽셀 검증 통과. 그래픽 설정 외 DataTable 필드 유지.

내구도 갱신이 기본 균열 머티리얼을 다시 지정하던 경로에도 외곽 적용을 연결했다. 이 검증은 초기 생성 시의 참조뿐 아니라 피해를 받은 뒤의 상태도 포함한다.
