# PIE 시작·종료 프로파일 — 2026-11-15

## 재현과 측정

128×128 광산, 약1.69만 블록, 저장된 시드로 각각3회 측정했다. Slate tick에서 PIE 요청 시각부터 플레이어·HUD가 준비된 첫 프레임까지, 종료 요청부터 월드 정리 후 에디터 tick으로 돌아오기까지를 잰다. 측정 중 실제 저장은 보호한다. 시작·종료의 디스크 저장 시간은 포함하지 않는 비교다.

| 상태 | 첫 시작 | 시작 평균 | 종료 평균 |
|---|---:|---:|---:|
| 수정 전 | 8.00초 | 8.02초 | 12.99초 |
| 블록 TEDS 중복 등록 제외 | 8.36초 | 8.03초 | 1.52초 |
| 경계 일괄 갱신 중간 측정 | 7.59초 | 7.14초 | 1.33초 |

중간 측정의 최저값을 최종 개선 수치로 사용하지 않는다. 최종 반복 실행 시작은7.28·7.34초였다. 최종 시작 평균은 약7%, 종료 평균은 약90% 줄었다. 마지막 코드에서는 시설 방 크기 계산으로 블록 수가16866개에서16886개로 소폭 달랐다. 큰 시설 V2 아트를 적용한 최종 마을 화면은 별도로 확인한다.

## 확인한 원인

Unreal Insights CPU trace에서 종료 시 `BroadcastPostReachabilityAnalysis` 하위의 `[TEDS] Post GC clean up` 한 번이 최대11.44초를 차지했다. 에디터의 계층 추적이 플레이 중 생성한 지형 액터와 하위 객체를 등록하고 GC 때 부모의 자식 배열에서 하나씩 제거하고 있었다. `UEditorEngine::EndPlayMap`은 한 번에 약12.9초였다.

시작에서는 블록 생성 도중 자기 자신과 이웃4칸의 경계를 계속 재계산했다. 아직 생성되지 않은 이웃까지 반영한 임시 모양을 반복 적용한 뒤 다시 덮어썼다. 첫 실행의 미로딩 스프라이트 때문에 `InitializeBlock`이 약1.7만 회 추가 호출되는 것도 trace로 확인했다.

## 변경

- ProjectMK 모듈이 공식 TEDS 등록 필터 API로 게임 월드의 `ABlockBase`와 그 하위 객체를 중복 등록에서 제외한다. 에디터 월드의 배치 액터와 다른 종류의 액터는 대상이 아니다. TEDS 전체를 비활성화하지 않으며 게임 빌드에는 이 의존성을 추가하지 않는다.
- 대량 생성 중 경계 갱신을 모으고 지형·시설·상자 배치가 끝난 뒤 블록마다 한 번 처리한다. 플레이 중 개별 채굴·설치·낙하의 주변 갱신은 유지한다.
- 해당 지형에 필요한 서로 다른 기본·광물 스프라이트를 먼저 로드하고, 액터가 이미지를 참조할 때까지 핸들을 유지한다. 첫 실행의 중복 비동기 초기화를 없앤다.
- 지지대의 윗면 보조 충돌은 실제 지지대에서만 만든다. 일반 블록마다 사용하지 않는 보조 BoxComponent를 생성하지 않는다.
- 세부 CPU trace 구간을 남겨 후속 프로파일에서 지형 생성·셀 생성·초기화·최종 경계 처리를 나눠 볼 수 있게 한다.

시작의 주요 잔여 비용은 약1.7만 개의 블록 액터와 Blueprint 컴포넌트 생성이다. 이번 변경은 전체 광산의 게임 규칙과 액터 기반 지형을 유지한다.

## 재측정

`AGENT/Scripts/BenchmarkPIE.py`를 `RunEditorPython.py`로 실행한다. 현재 PIE가 실행 중이면 측정을 시작하지 않는다. `Saved/AgentLogs/pie-benchmark-config.json`에 tag·runs·trace를 지정할 수 있다. 결과와 trace는 같은 폴더의 `pie-<tag>.json`, `.utrace`에 저장한다.

기준 파일은 `pie-before`, `pie-filtered`, `pie-batched`, `pie-final-performance`다. `TimingInsights.ExportTimerStatistics`로 CSV를 추출해 비교했다. 개발 비교용 콘솔 변수는 `mk.Editor.TrackPIEBlocksInTEDS` (기본0), `mk.World.BatchTerrainEdges` (기본1)다.

플레이 중이던 사용자 세션은 정상 종료해 저장한 뒤 `BeforePIEPerformance-20261115-071446/AfterUserSession`에 복사했다. 성능 측정은 그 이후의 파일을 덮어쓰지 않는다.
