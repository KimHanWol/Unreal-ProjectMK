# 플레이 테스트 목업

## 범위

- 에디터의 PIE에서만 테스트 패널과 퀵슬롯을 자동 생성한다. 별도 액터 배치는 필요 없다.
- 제작 화면은 기존 메뉴의 C 키에 연결한다. 상점과 마찬가지로 위젯 블루프린트 없이 기본 레이아웃을 만든다.
- 테스트 패널은 `UPlaytestWidget`, 하단 퀵바는 독립된 `UQuickInventoryWidget`으로 나눈다. F1은 테스트 패널만 접는다.
- 정식 HUD와 테스트 도구가 준비되면 `AMKPlayerController::CreatePlaytestWidget`의 PIE 자동 생성 경로와 `UPlaytestWidget`을 제거한다. 퀵바는 정식 HUD 배치에 재사용할 수 있다.
- 제작 위젯 블루프린트가 이미 등록되어 있으면 기존 메뉴 캐시가 해당 위젯을 우선한다.

## 조작

| 입력 | 동작 |
|---|---|
| A / D | 좌우 이동, 해당 방향 채굴 |
| W / S | 위 / 아래 방향 채굴 |
| Space | 비행 |
| R 누르기 | 자석 수집 |
| E / 상점 클릭 | 근처 상점 열기 |
| C | 제작 열기 / 닫기 |
| K | 스킬트리 열기 / 닫기 |
| 1~8 / 하단 퀵슬롯 클릭 | 인벤토리 첫 8칸 아이템 사용 |
| F1 / 패널 제목 클릭 | 테스트 도구 접기 / 펼치기 |

메뉴가 열린 동안 캐릭터 입력을 막는다. C / K로 다른 메뉴에 바로 전환할 수 있다. 메뉴의 닫기 버튼으로 플레이에 복귀한다. Escape는 기존 PIE 종료 동작을 유지한다.

## 테스트 도구

- **재료 세트:** 현재 소모품 레시피의 재료를 종류별 최대 30개 지급한다. Slime도 포함한다. 이번 플레이의 인벤토리를 교체한다.
- **소모품 세트:** 소모품 레시피의 결과 아이템을 종류별 최대 3개 지급한다. 이번 플레이의 인벤토리를 교체한다. 슬롯 수가 부족하면 실제 지급한 종류 수를 표시한다.
- **코인 +1,000:** 코인 배율 없이 지급한다. 레시피와 스킬 구매 테스트에 사용한다.
- **상점:** 거리 조건 없이 기존 상점 메뉴를 연다.
- **체력 -25 / 산소 -40% / 회복:** 기존 GameplayEffect 유틸 경로로 수치를 조절한다. 지상에서는 산소가 바로 회복되므로 산소 캡슐 테스트는 지하에서 한다.
- **지상 복귀:** 귀환 대기를 취소하고 스폰 위치로 이동한다.
- **상태 표시:** 실제 GAS 체력·산소·코인, 지형 시드, 저장 모드, 귀환 남은 시간을 표시한다.

테스트 지급이나 수치 조절, 강제 복귀를 처음 사용하면 해당 PIE 세션은 **파일 저장을 중단**한다. 이후 판매·제작·스킬 구매·사망·종료 시에도 원래 세이브 파일과 백업을 덮어쓰지 않는다. 이 모드는 해당 GameInstance가 끝날 때까지 유지한다. PIE를 종료하고 다시 시작하면 원래 저장 데이터를 읽고 일반 저장 모드로 돌아간다. 테스트 도구를 사용하지 않은 일반 플레이는 기존 자동 저장을 유지한다.

## 퀵바 전용 레이아웃

- `UQuickInventoryWidget`이 하단 프레임·제목·8칸·귀환 안내를 담당한다. 인벤토리 창과 테스트 패널의 레이아웃을 사용하지 않는다.
- 각 칸은 `UPlaytestQuickSlotWidget`이다. 키 번호는 왼쪽 위, 아이콘은 중앙, 수량은 오른쪽 아래, 이름은 하단에 배치한다. 사용 가능한 소모품은 청록색 배경으로 구분한다.
- `BP_PlayerController.QuickInventoryWidgetClass`에 `UQuickInventoryWidget`을 상속한 WBP를 지정하면 별도 레이아웃으로 교체할 수 있다. `HBox_Slot`(HorizontalBox)과 선택적 `RecallText`(TextBlock)를 사용한다.
- 슬롯 WBP는 `QuickSlotClass`에서 교체한다. 바인딩 이름은 `UseButton`, `FrameBorder`, `ItemIcon`, `KeyText`, `CountText`, `ItemNameText`이다.
- 기본 레이아웃의 위치는 `ViewportAnchor` / `ViewportOffset`, 슬롯 크기는 `SlotSize`로 조정한다.
- 데이터 연결은 기존 규칙대로 인벤토리의 첫 8칸을 사용한다. 별도의 퀵슬롯 아이템 지정 시스템을 추가하지 않는다.

## 확인 순서

1. Main 맵을 PIE로 시작하고 오른쪽 패널과 하단 8칸이 보이는지 확인한다.
2. 재료 세트와 코인을 지급한다. 상태가 `테스트 · 파일 저장 꺼짐`으로 바뀌는지 확인한다.
3. 상점에서 산소 캡슐 레시피를 구매한다. 구매 버튼과 코인이 갱신되는지 확인한다.
4. C로 제작 화면에 전환한다. 해금 상태와 재료 보유 / 필요 수량을 확인하고 제작한다.
5. 지하에서 산소를 줄이고 산소 캡슐을 사용한다. 소모품 세트로 나머지 소모품도 확인한다.
6. 지상에서 버팀목, 완충 젤, 발파 폭약을 사용한다. 공중 설치 실패와 아이템 미소모를 확인한다.
7. 귀환 대기 표시와 이동 취소를 확인한다. 보험을 소지하고 사망 페널티도 확인한다.
8. 메뉴를 닫은 뒤 이동·드릴·비행과 숫자 키가 정상 작동하는지 확인한다.
9. PIE를 종료하고 다시 시작해 테스트 지급이 원래 세이브에 반영되지 않았는지 확인한다.

## 검증 상태

- 소스 정적 검토 대상: 위젯 등록, 이벤트 해제, PIE 전용 생성, 테스트 모드의 저장 차단, 엔진 5.8 API 선언.
- 2026-10-18 에디터 빌드와 PIE 검증 완료. 아래 결과를 참고한다.

### 2026-10-18 제작창 진입 조사

- 실행 중인 에디터는 `Binaries/Win64/UnrealEditor-ProjectMK.dll`을 로드하고 있으며 DLL 수정 시각은 2026-09-29 22:04(한국 시간)이다. 새 제작창 / 목업 소스는 2026-10-18에 수정됐다.
- 에디터 ObjectTools 조회에서 `/Script/ProjectMK.Default__MKMenuBase.RuntimeMenuContentsClasses`는 `ShopMenuContents`만 포함한다. 새 `PlaytestWidget` 클래스 검색 결과도 비어 있다.
- 따라서 현재 실행 모듈에는 새 제작창 등록과 목업이 반영되지 않았다. 수정된 코드로 빌드·재실행하기 전에는 C 키 제작창과 새 퀵바의 실제 동작을 검증할 수 없다.

### 2026-10-18 빌드 및 PIE 검증 결과

- 사용자 승인 후 에디터 종료 전에 프로젝트 자산 72개와 Main 맵의 dirty 상태를 확인했다. 저장되지 않은 변경은 없었다. 지정된 StopEditor → BuildEditor → StartEditor 스크립트를 사용했다.
- 첫 빌드에서 두 위젯의 지역 변수 `Slot`이 `UWidget::Slot`을 가리는 C4458 오류 3건을 확인했다. `ButtonSlot` / `QuickSlot`으로 수정하고 재빌드해 `Result: Succeeded`, `BUILD_EXIT=0`을 확인했다.
- 재시작한 에디터의 네이티브 메뉴 등록에서 `ShopMenuContents`와 `CraftingMenuContents`가 모두 조회됐다.
- Main 맵의 별도 PIE 창에서 플레이 영역에 포커스를 주고 C 키로 제작창 열기와 닫기를 확인했다. 상점에서 C로 제작창에 바로 전환하는 동작도 확인했다.
- 재료 세트 지급 후 제작 가능 상태와 보유 수량이 갱신됐다. 산소 캡슐을 제작하자 Coal 30 → 27, Copper 30 → 29로 줄었고 7번 슬롯에 산소 캡슐 1개가 생겼다.
- 상점에서 응급 키트 레시피를 구매하자 코인이 1,078 → 1,048로 줄고 제작 버튼이 활성화됐다. 이어 제작 완료 표시도 확인했다.
- 소모품 세트는 7/7종을 지급했다. 체력을 낮춘 뒤 숫자 키 6으로 응급 키트를 사용하자 체력 100과 수량 3 → 2를 확인했다. 다시 체력을 낮춘 뒤 퀵슬롯을 클릭하자 체력 100과 수량 2 → 1을 확인했다. 체력이 가득할 때 클릭하면 수량이 줄지 않았다.
- F1은 테스트 패널만 접었으며 전용 퀵바는 계속 보였다.
- PIE 종료 후 원본 및 백업 세이브의 SHA-256이 테스트 전과 같았다. 두 파일 모두 `A16B0A1E2A76FEDEF76D2D5C16C6B2A7DA903EB008B29E0CBF610AEC1D0812B1`이다.
- 스크린샷: `output/playtest/crafting-keyboard.png`, `output/playtest/quickbar-tested.png`.
- 테스트 종료 후 에디터는 Main 맵을 연 상태로 유지했다. 기존 시작 로그의 구조체 초기값 및 GameFeatureData 설정 오류는 이번 UI 변경 범위에서 수정하지 않았다.
