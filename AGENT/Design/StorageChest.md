# 보관 상자

## 사용 흐름

- `ItemDataTable.StorageChest`는 설치 가능한 소모품이며 퀵슬롯에 넣어 사용한다. 바닥 위 빈 칸에 설치 성공 시 1개를 소모한다. 작업대·다른 상자와 겹치거나 공중이면 실패한다.
- 상자 자체는 캐릭터와 충돌하지 않는다. 근처에서 짧게 F를 눌러 열고, F를 0.8초 유지하면 빈 상자를 회수한다. 내용물이 있거나 인벤토리 공간이 없으면 회수하지 않는다. 매장된 동안에는 보이지 않고 상호작용도 할 수 없다.
- 5열 2행의 보관함 10칸만 독립된 작은 창으로 연다. 오른쪽 플레이어 영역, 복제된 소지품 영역, 화면 전체 딤드는 없다. 플레이어 이동 입력도 막지 않는다.
- 기존 HUD의 우하단 인벤토리와 하단 퀵슬롯을 그대로 드래그 대상으로 사용한다. 슬롯·개수·툴팁·드래그 고스트는 공통 UItemSlotWidget이다.
- 드래그로 상자·인벤토리·퀵슬롯 사이 이동, 합치기, 교환을 지원한다. 광물은 퀵슬롯에 넣을 수 없다. 상자 슬롯 우클릭은 인벤토리로 빠르게 꺼내기이며 기존 스택부터 합친 뒤 빈 칸을 사용한다.
- X, 같은 상자에서 F를 다시 누르기, 상호작용 범위 이탈, 상자 파괴, 다른 모달 메뉴 열기로 창을 닫는다. 창 밖의 HUD에 마우스 입력이 그대로 전달된다.
- 상자 바깥에 버리는 경우 기존 수량 팝업을 사용한다. 소지품과 상자 내용물은 분리되어 있어 제작 재료·판매 보유량은 플레이어 소지품만 센다.
- 상자 레시피나 상점 판매 행은 추가하지 않는다. 지하 매장 상자를 발견해 사용하고, 폭파하여 빈 상자를 회수해 옮길 수 있다. 치트 UI의 `상자 설치` 버튼으로 근처 바닥에 실제 상자를 설치한다. 빈 자리가 없으면 상자 아이템 지급을 시도한다. 기존 `GiveItem StorageChest`도 유지한다.

## 블록 낙하와 장식 상자 구분

실제 보관 상자는 `StorageChest` 블록 행(TileIndex 902)의 물리 몸체에 부착된다. 몸체는 지형 블록 맵에 등록되고, 지지 연결이 끊어지면 일반 블록의 흔들림·낙하·정착 처리를 따른다. 내용물·상자 ID·상호작용 영역은 함께 움직인다. 캐릭터는 통과할 수 있고, 낙하 중에는 상호작용하지 않으며 착지하면 다시 F로 열 수 있다. 보관 상자 자체는 낙하 충격으로 내용물을 잃지 않는다.

`bFallsWhenUnmineable`은 채굴 불가지만 떨어질 수 있는 블록을 구분하는 데이터 값이다. 기반암·경계·기존 앵커의 낙하 규칙은 유지한다. 폭약은 상자 소유 액터에서 처리해 빈 상자와 내용물을 각각 드롭하고 물리 몸체를 함께 제거한다.

기존 `SupplyCrates` 나무 상자 더미는 장식 액터였으므로 F 가이드와 보관 기능이 없었다. 지상·지하의 해당 배치 지점은 이제 실제 빈 보관 상자로 생성한다. 매장 상자는 별도 희귀 생성 규칙과 무작위 전리품을 그대로 사용한다. 새 버전에서 생성하는 상자는 닫힌 뚜껑·철제 띠·황동 잠금쇠 실루엣으로 구별한다.

## 발파와 회수

상자와 내용물은 함께 운반되는 아이템이 아니다. 발파 범위 안의 상자는 빈 상자 아이템 1개와 각 보관 슬롯의 물품을 각각 필드에 드롭하고 사라진다. 같은 자리를 다시 폭파해도 복제되지 않는다. 드롭한 빈 상자를 회수해 설치하면 빈 보관함이 생긴다.

드롭 스폰이 실패하면 이미 스폰한 드롭을 취소하고 상자와 내용물을 유지한다. 일반 드롭과 같은 수집·점멸·소멸 규칙을 쓴다. 필드 드롭의 영속 저장은 기존 시스템과 마찬가지로 포함하지 않는다.

## 매장 생성

GameSettingDataAsset.MineableLevelGeneration에서 다음을 조정한다.

| 값 | 기본값 |
|---|---|
| BuriedChestChancePerBlock | 0.0006 (후보 블록당 0.06%) |
| BuriedChestMaxCount | 16 |
| BuriedChestMinimumDepth | 지표 아래 6칸 |
| BuriedChestMinimumSpacing | 맨해튼 거리 8칸 |
| ChestLootRollCount | 2~4회 |
| ChestLootTable | 기존 아이템 키·가중치·수량 범위 |

같은 지형 시드는 같은 매장 위치·식별자·전리품을 만든다. 실제 채굴 가능한 블록 안에 상자를 숨기며, 덮고 있던 블록이 파괴되거나 이동하면 설치된 상자가 드러난다. 확률 생성이므로 월드마다 반드시 같은 개수가 생기는 것은 아니다.

현재 전리품은 석탄·구리·철·산소 캡슐·응급 키트·버팀목·귀환 신호탄 중 가중치로 고른다. 새 몬스터나 새로운 보상 상자 종류는 가정하지 않는다. 일회 유물 보상은 아직 포함하지 않는다.

## 저장과 자원

- 설치 위치·10칸 내용물·발견 여부·상자 ID와 파괴 ID를 저장한다. 파괴한 매장 상자는 시드로 다시 생성되더라도 제거해 내용물 재획득을 막는다.
- 기존 지형은 시드로 복원하므로 이미 발견했거나 플레이어가 설치했던 상자의 칸을 다시 막지 않게 비운다. 주변 채굴 지형 전체의 영속 저장을 추가하는 것은 아니다.
- 전용 닫힌 나무 상자 `/Game/Asset/StorageChestV3/S_StorageChest`를 필드·아이템·보관함 제목 아이콘에 공통 사용한다. 32×32 원본, 2px/월드 단위, MaskedUnlit. [제작 기록](../Art/STORAGE_CHEST_V3.md)을 따른다.
- `AGENT/Scripts/ApplyStorageChestData.py`로 아이템 행·스프라이트·전리품·생성 기본값을 재적용한다. 다른 아이템과 레시피 행은 보존한다.

## 기존 패턴의 확정 등장

`GuaranteedStructurePatterns`는 기존 OreVault, HarvestSlab, BaitTrap 중 선택한다. 지정한 패턴은 무작위 추가 구조물보다 먼저 배치한다. 무작위 위치 재시도가 실패하면 작은 규격으로 후보 위치를 순서대로 탐색한다. 결과에는 Pattern과 bGuaranteed를 기록한다.

기본값은 기존 3패턴을 각각 최소 1개다. 무작위 밀도에 따른 목표 개수가 더 작아도 확정 목록을 먼저 충족한다. FallingStructureCount=0 또는 해당 목적의 생성 스위치를 끄면 해당 패턴은 생성하지 않는다. 확정 배치가 물리적으로 불가능한 크기의 월드는 경고를 남기므로, 월드 크기를 줄였을 때에는 배치 가능성을 확인해야 한다. 새 몬스터 종류는 추가하지 않고 BaitTrap은 기존 StructureMonsterRowKey를 따른다.

상자 V3는 기존 광산 소품을 직접 참고한 회갈색 목재·짙은 철제 띠를 사용한다. 32×32 캔버스의 마지막 행까지 상자 바닥을 붙여 기존 2px 투명 여백을 제거했다. 물리 몸체는 유지하고 렌더 스프라이트만 Y=-12, 정렬 우선순위 -4로 옮겨 캐릭터 뒤에 표시한다.
