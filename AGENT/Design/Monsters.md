# 몬스터

## 데이터와 배치

- `MonsterDataTable`은 `FMonsterDataTableRow`를 사용한다. `DA_DataTable.DataTableList`의 `Monster` 항목으로 연결하며 게임 로직은 `UDataManager`를 통해 조회한다.
- 기본 행은 `DrillCrawler`다. 월드에 `MKMonster`를 배치한 뒤 `MonsterDataRowKey`로 행을 선택한다. DataTable 수정은 다음 소환 또는 다음 PIE부터 적용된다.
- 체력·이동 속도·드릴 위력·드릴 주기는 기존 캐릭터 GAS AttributeSet을 사용한다. 실제 수치를 별도 체력 변수에 중복 저장하지 않는다.
- 외형은 DataTable의 `Sprite`, `SpriteSize`, `NormalColor`, `AngryColor`로 바꾼다. 현재는 기존 슬라임 아이콘을 사용한 목업이다.

## 행동

- `IdleDurationMin/Max` 사이의 시간 동안 정지한 뒤, 무작위 좌우 방향으로 `MoveDurationMin/Max` 동안 배회한다. 이동이 끝나면 다시 Idle로 들어간다.
- `WanderRadiusCells` 범위 안에서 움직인다. 벽이나 낭떠러지를 만나면 안전한 반대쪽으로 돌아서며, 양쪽 모두 막혔으면 쉰다. 지형이 무너지면 중력에 따라 떨어진다.
- 피격 시 분노를 처음부터 시작한다. `AngryDuration`(기본 4초) 제한 시간과 `DrillCellsMin/Max`(에디터 표시: Drill Count Min/Max, 기본 2~3개) 파괴 횟수를 매번 초기화한다. 이미 분노해서 채굴 중일 때 맞아도 현재 목표를 해제하고 새 행동을 시작한다.
- 분노 중 무작위 좌우 방향으로 이동하다가 가까운 상하좌우 블록 중 하나를 고른다. 원거리 탐색은 하지 않는다. 캡슐 표면에서 최대 2.5 단위까지 짧게 추적하여 처음 맞는 블록만 선택하고, 매 타격 전 같은 거리와 가림 조건을 다시 확인한다.
- 블록 하나에 `DrillWindup` 예고 후 `DrillingPeriod`마다 `DrillingPower` 내구도 피해를 준다. 완전히 파괴하면 다시 이동하고 다음 블록을 고른다. 정해진 2~3개를 부수거나 제한 시간이 지나면 Idle로 돌아간다. 제한 시간이 먼저 끝나면 실제 파괴 수는 더 적을 수 있다.
- 채굴 성공이나 대상 재탐색은 분노 제한 시간을 연장하지 않는다. 주변 블록이 없거나, 파괴에 오래 걸리거나, 낙하 중이어도 마지막 피격부터 정해진 시간이 지나면 종료한다. 낙하 중에는 드릴링하지 않는다.
- 암석·상점·경계처럼 채굴 불가능한 블록을 건너뛰어 뒤쪽 블록을 공격하지 않는다. 기존 블록 내구도 피해 경로를 사용하므로 드롭·붕괴·미니맵 갱신도 적용된다.
- 플레이어 드릴은 블록에는 내구도 피해, 몬스터에는 체력 피해를 준다. 몬스터의 체력이 0이면 제거한다.

## 접촉 피해와 테스트

- 몬스터 캡슐과 플레이어가 겹치면 `ContactDamage`만큼 체력 피해를 준다. 겹쳐 있는 동안 `ContactDamageInterval` 간격으로 반복하며, 잠깐 떨어졌다 붙어도 간격을 우회하지 않는다. 기존 플레이어 피격 무적도 유지한다.
- 접촉 판정은 몬스터 캡슐과 플레이어 몸 캡슐의 실제 겹침으로 제한한다. 아이템 수집용 InventoryComponent 구체만 겹치면 피해와 넉백을 주지 않는다.
- 접촉으로 실제 체력이 감소했을 때만 몬스터에게서 멀어지는 수평 속도와 작은 상승 속도로 한 번 튕겨 오른다. `ContactKnockbackSpeed`(기본 90 단위/초), `ContactKnockbackUpwardSpeed`(기본 80 단위/초), `ContactKnockbackDuration`(에디터 표시 Knockback Recovery Time, 기본 0.18초)을 MonsterDataTable에서 조절한다. 수평 속도 또는 회복 시간이 0이면 넉백을 끈다. 무적으로 피해가 막히거나 사망해 리스폰한 경우에는 적용하지 않는다.
- 넉백은 LaunchCharacter로 한 번만 속도를 주며, 이후 궤적은 중력과 충돌로 결정한다. 계속 미는 RootMotionSource는 사용하지 않는다. 짧은 회복 시간 동안 이동·방향 입력과 비행 속도 덮어쓰기를 막아 튕김을 보존한다. 비행 키를 계속 누르고 있으면 회복 후 다시 비행한다.
- 몸은 몬스터에게서 튕겨 나가지만 스프라이트는 피격 직전 바라보던 방향의 Idle을 유지한다. 회복 뒤 새 방향 입력을 주면 다시 방향이 바뀐다. 리스폰과 EndPlay 때 회복 타이머를 정리한다.
- PIE 테스트 패널의 `몬스터 소환`은 플레이어 옆에 1마리를 소환한다. 다시 누르면 앞서 소환한 테스트 몬스터를 교체한다.
- `몬스터 자극`은 해당 몬스터에게 10 피해를 준다. 직접 드릴로 공격해서도 분노시킬 수 있다.
- 테스트 버튼은 기존 테스트 세션을 시작해 이번 플레이의 파일 저장을 중단한다. 저장 파일에 테스트 피해·채굴 결과를 남기지 않는다.
- 머리 위 `IDLE / ROAM / ANGRY`와 체력 숫자로 상태를 확인한다. 분노하면 색상이 바뀌고 선택한 드릴 방향을 화살표로 표시한다.
- 행동·접촉 피해는 0.1초 타이머로 처리한다. Tick은 CharacterMovement에 이동 입력을 전달하는 데만 사용한다.

## 검증 (2026-10-18)

- Development Editor 빌드 성공. 기존 `SkillSlotWidget`의 Cast 경고는 남아 있다.
- 실제 `MonsterDataTable`을 생성하고 `DA_DataTable`의 기존 연결을 유지한 채 Monster 항목을 추가했다. 기본 행과 설정값을 저장 후 다시 읽어 확인했다.
- DataTable에서 일시적으로 이동 속도 0 / Idle 30초를 지정해 접촉 테스트를 수행하고, 종료 전 기본값(이동 20 / Idle 0.6~1.6초)을 복구·저장했다.
- 기본값에서 `Idle → Wandering → Idle` 전환과 X 970.2~990.2 사이의 좌우 이동·정지를 연속 샘플로 확인했다.
- 몸이 떨어져 있을 때 체력 100 유지, 실제 겹침 후 100 → 88 피해와 후속 샘플의 무적·자연 회복 적용을 확인했다. 테스트는 기존 플레이어의 체력 재생과 피격 무적을 유지한 상태로 수행했다.
- 자극 버튼 피격 후 `ANGRY 70/80` 표시와 블록 수 2,085 → 2,084 감소를 확인했다. 채굴 불가 암석을 통과하지 않고 실제로 파괴된 공간이 표시됐다.
- 추가 피격으로 체력이 0이 되면 몬스터 액터와 상태 위젯이 함께 제거되는 것을 확인했다.
- 수동 PIE 검증과 마지막 자동 검증 각각 종료 후 기본·백업 세이브 파일 해시가 해당 검증 시작 전과 같음을 확인했다. Main 레벨 자산에 몬스터를 자동 배치하거나 테스트 지형을 저장하지 않았다.
- `ProjectMK.PIE.Monster.PlayerDrillTriggersAnger` 자동 테스트 통과(2.55초). 기본 드릴 주기 0.5초를 유지하고 D 입력을 1.5초 동안 전달해 몬스터 체력 80 → 40과 분노 전환을 확인했다.
- 자동 테스트는 Main 맵이 열려 있는 상태에서 실행한다. 자체적으로 PIE를 시작·종료하고, 테스트 세션으로 저장을 차단하며, 이동 속도를 일시적으로 0으로 고정해 타격을 확인한 뒤 복구한다. 에디터 전용 테스트 의존성은 게임 빌드에 포함하지 않는다.
- 기존 GameplayCue 경로 미설정 / HUD 중복 추가 경고가 자동 테스트 로그에 남지만 테스트 오류는 없다.
- 화면 기록: `output/playtest/monster-angry.png`.
- 원거리 채굴 제거 후 Development Editor 빌드 및 자동 테스트 5개 통과(총 20.41초): SequentialSingleBlockDrilling, EmptyAreaAngerTimeout, HitWhileDrillingRestartsAnger, PlayerDrillTriggersAnger, OneCellShaftCollision.
- 순차 채굴 검증은 2개 완전 파괴 / 미완성 0개였고, 매 피해 시점에 캡슐 바로 앞의 블록인지 확인했다. 이동 전 원거리 목표에 피해를 주는 이전 구현은 이 조건을 만족하지 못한다.
- 채굴 불가 바닥만 있는 곳에서는 마지막 피격 후 4.00초에 종료했다. 내구도가 높은 블록을 실제 채굴하는 중 다시 공격했을 때 기존 종료 시점을 지나서도 분노했고, 마지막 피격 후 4.10초에 종료했다. 채굴 자체로 제한 시간을 연장하지 않는다.
- 자동 검증은 테스트 세션으로 저장을 차단했다. 별도 화면 확인 PIE의 정상 저장 전후에는 Unreal 커스텀 버전 헤더 순서만 달랐고, 저장 클래스와 실제 게임 데이터 바이트는 동일했다.
- 튕김 방식으로 변경한 뒤 Development Editor 빌드와 자동 테스트 6개가 모두 통과했다(총 25.00초). ContactKnockback 테스트는 좌우 접촉, 회복 중 방향 입력, 비행 중 접촉, 무적, 벽 충돌, 몸이 떨어진 수집 구체 겹침을 검증한다.
- 기본 상승 속도 80에서 최고 상승 높이는 3.26 단위였고, 상승·하강 후 착지를 확인했다. 입력 없는 지상 넉백은 17.62 단위 이동했고, 벽에서는 2.91 단위에서 정지했다. 무적 또는 수집 구체만 겹친 경우에는 체력 100과 이동·상승 0을 유지했다.
- 넉백 중 실제 스프라이트의 Idle_Left/Idle_Right 자산 경로를 검사해 피격 직전 방향이 유지되는 것을 확인했다. 회복 중 이동 입력에도 방향을 유지하고, 비행은 잠시 Falling으로 전환한 뒤 비행 키가 눌려 있으면 회복 후 Flying으로 복귀했다. RootMotionSource가 없다는 것도 검사했다.
- 기존 접촉 판정의 GetOverlappingActors가 InventoryComponent 겹침까지 포함하는 것을 재현했다. 13 단위 떨어져 몸 캡슐이 닿지 않은 상태에서도 피해가 발생하던 문제를 캡슐 간 겹침 검사로 수정하고, 같은 조건에서 피해·넉백이 발생하지 않는 것을 확인했다.
- 기존 드릴 입력 검증도 몬스터 체력 80 → 40으로 통과했다. 이전 ConstantForce 방식은 LaunchCharacter 충격 방식으로 교체했다.
- 넉백 검증 종료 후 기본·백업 세이브 파일 해시는 검증 시작 전과 동일했으며 Main 레벨도 저장 변경이 없다.
